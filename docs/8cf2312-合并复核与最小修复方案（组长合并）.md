## 二、确定回归点（子任务 native-path-regression，全部附 A/B 运行时对照）

### 回归 A（高严重，原生模型正文丢失）——「泄漏」被换成「丢失」

- **触发条件**：模型正文含**行首裸工具标签**（18 个 BUILTIN 名或声明名，如 `<run_command>`），且流以原生 `tool_calls` 收口。
- **机制**：正文行首裸标签 → `findEarliestBareMarkerIdx` 截断（1260-1263）→ 下一帧 `alreadyInsideToolBlock=true` 整帧吞（1241-1247）→ 收口走 `pendingToolCalls` 分支（1343-1375）或 `tool_calls` 分支（1423-1455）时 **`parts = emitParts.slice()` 不含被扣留文本且不执行 1411 的 flush** → 直接 return。
- **复现序列**（streamKey 任意，无声明 schema）：
  1. `{delta:{content:'方法一是在终端运行：\n<run_command>'}}`
  2. `{delta:{content:'（注意标签要闭合）', tool_calls:[{index:0,id:'tc1',function:{name:'list_dir',arguments:'{"path":"."}'}}]}, finish_reason:'tool_calls'}`
- **A/B 对照（实测）**：
  - OLD：`文本="方法一是在终端运行：\n<run_command>（注意标签要闭合）" 调用=["list_dir"]`（标签泄漏但正文完整）
  - NEW：`文本="方法一是在终端运行：\n" 调用=["list_dir"]` —— **「（注意标签要闭合）」永久丢失**
- **变体**：`finish_reason='function_call'`（R1b）、`finish_reason='stop'` + pendingNative（R2）、声明 schema 会话（R4）——四种收口形态实测全部丢失。
- **行号**：丢失点 1345 / 1424（`emitParts.slice()` 后直接 return）；hold 点 1241-1247、1260-1263、1270-1283。

### 回归 B（高严重，**所有模型**文本损坏）——`emittedLen` 记账错位

- **触发条件**：任意模型（无需原生调用），一个 tool-call marker（标准或裸）**跨 chunk 切分**，且后续帧恢复正常发射，流以 stop 收口且未解析出调用。
- **机制**：`emittedLen` 按「已发射字符数」累加（1290），但 `accumulatedText` 还包含被 hold 的前缀（如 chunk1 尾的 `<tool_`/`<run_`）。下一帧正常发射后 `emittedLen` 落后于真实已发射前缀位置 → 收口 `slice(emittedLen)`（1411）把**已发射过的尾部当未发射重发**（重复），同时被 hold 的前缀**永不补发**（丢失）。`shared.ts:17` 注释 "emission is strictly prefix-based" 的假设在 hold 后不成立。
- **复现序列**（C2，标准 marker 即可，与裸标签无关）：
  1. `{delta:{content:'示例：<tool_'}}`
  2. `{delta:{content:'call>{"x":1}\n说明正文。'}}`
  3. `{delta:{}, finish_reason:'stop'}`
- **A/B 对照（实测）**：
  - OLD：`文本="示例：call>{\"x\":1}\n说明正文。"`（丢 `<tool_` 前缀——既有泄漏缺陷）
  - NEW：`文本="示例：call>{\"x\":1}\n说明正文。\n说明正文。"` —— **丢 `<tool_` 且尾部重复**
- **行号**：记账点 1290、hold 点 1281-1283、flush 点 1411；中间帧清零点 1329。
- **说明**：回归 B 触发不依赖原生路径，文本标签模型、纯文本模型同样中招；这是前版核验文档 Patch 1e 设计本身的缺陷被 8cf2312 原样落地。

### 正向确认（泄漏修复确实生效，不可回退）

- C3/C5 实测：闭合裸标签 `<run_command>{"CommandLine":"git status"}` → NEW 调用正常发射且**无标签泄漏**（OLD 标签泄漏为正文）。
- R3 实测：纯净原生流（正文 + 分帧 native tool_calls + finish=tool_calls）→ NEW 与 OLD 输出完全一致，`list_dir` 调用参数正确。
- R5 实测：正文含行首裸标签 + 参数体 + stop 无调用 → NEW 全文完整补发、无误发 functionCall（flush 设计在**无后续发射**场景正确）。

## 三、最小修复方案（子任务 minimal-fix-design：只出方案与 diff 草案，不改代码）

设计原则：**泄漏修复与 RC2/RC5/RC8 收口修复全部保留**；原生路径文本发射行为恢复到 8cf2312 之前；记账模型换成显式缓冲。

### 补丁 1（必修，治回归 B 根因）：`emittedLen` 记账 → `withheldText` 显式缓冲

`emittedLen` 的「前缀连续」假设在 hold 后必然错位（回归 B）。改为直接记录「被扣住的文本」，flush 时原样补发，天然不会重复：

```ts
// shared.ts:15-17 —— 以 withheldText 取代 emittedLen
pendingHeldSuffix?: string;
/** 已被发射层扣留、尚未作为可见文本发出的正文（收口时原样补发）。 */
withheldText?: string;
```

```ts
// openai.ts 发射区（1245-1292）：
if (text) {
  if (alreadyInsideToolBlock) {
    context.withheldText = (context.withheldText ?? '') + text;          // ① 整帧吞 → 记入缓冲
  } else {
    let earliestIdx = -1;
    // ……标准 marker 扫描（1250-1255）不变……
    const bareIdx = findEarliestBareMarkerIdx(context.accumulatedText, text, prevAcc.length, leanToolNames);
    if (bareIdx >= 0 && (earliestIdx === -1 || bareIdx < earliestIdx)) earliestIdx = bareIdx;

    let safePrefix = earliestIdx >= 0 ? text.slice(0, earliestIdx) : text;
    if (earliestIdx === -1) {
      // ……partial holdback（1264-1286）不变……
      if (holdLen > 0) {
        safePrefix = safePrefix.slice(0, safePrefix.length - holdLen);
        context.pendingHeldSuffix = text.slice(text.length - holdLen);
        context.withheldText = (context.withheldText ?? '') + context.pendingHeldSuffix;  // ② 前缀 hold → 记入缓冲
      } else {
        delete context.pendingHeldSuffix;
      }
    } else {
      context.withheldText = (context.withheldText ?? '') + text.slice(earliestIdx);      // ③ 截断余量 → 记入缓冲
    }
    if (safePrefix) emitParts.push({ text: safePrefix });   // ④ 不再累加 emittedLen
  }
}
```

```ts
// 中间帧发射（1328-1329）：
context.accumulatedText = '';
context.withheldText = '';            // 扣留文本已被解析消费
// （RC8 的 1334 保持不变）

// 收口 flush（1406-1413）：
const held = context.withheldText;
if (held) emitParts.push({ text: held });
delete context.pendingHeldSuffix;
context.withheldText = '';
activeStreamContexts.delete(streamId);
```

**等价性论证（对 R5/C3/C5 无行为变化，对 C2 修复）**：
- 无 hold 的流：`withheldText` 恒空 → flush 与不 flush 均无差异 → **零行为变化**。
- R5 型（hold 后无后续发射直到收口）：扣留文本在收口全额补发 → 与 8cf2312 现行为一致（实测 R5 已正确，保持）。
- C2 型（hold 后有后续发射）：`<tool_` 在②处入缓冲，后续发射不再污染任何计数 → 收口补发 `<tool_`、不重复尾部 → **修复回归 B**。
- 泄漏语义不变：标记在流式过程中仍被扣住不闪烁，仅推迟到收口——泄漏修复完整保留。

### 补丁 2（必修，治回归 A）：两处原生收口分支补发扣留正文（含细化）

```ts
// 1343-1375（pendingToolCalls 分支）与 1423-1455（tool_calls 分支），parts 组装处：
const parts: GeminiPart[] = emitParts.slice();
const held = context.withheldText;
if (held && !withheldStartsWithMarkup(held)) parts.unshift({ text: held });
// ……后续 functionCall 组装逻辑逐行不动……
```

**细化说明**：原始方案为无条件 `unshift`，实测会破坏既有回归用例 **d2**（正文 DSML 与 native `delta.tool_calls` 并存时 DSML 不泄漏）：收口时把被扣留的 `\n</DSML|tool_calls>\n` 标记原样泄漏为正文。因此细化为**前缀判别**：

```ts
// 新增辅助函数（openai.ts:303-308）：
function withheldStartsWithMarkup(held: string): boolean {
  for (const marker of TOOL_CALL_START_MARKERS) {
    if (held.startsWith(marker)) return true;
  }
  return false;
}
```

- 扣留文本以 `TOOL_CALL_START_MARKERS` 任一标记开头（如 `<DSML|`、`<tool_call`、`<tool ` 等）→ 视为被原生 `delta.tool_calls` 调用取代的废弃调用块 → **维持丢弃，不泄漏**（d2 语义保持）；
- 扣留文本以纯文本开头 → 误扣正文（回归 A 触发形态）→ **随调用帧原样补发**（h4/h5 正向语义）。

**等价性论证**：
- 无 hold：`held` 为空 → `unshift` 不执行 → 三段原生路径（1220-1228 / 1343-1375 / 1423-1455）**零行为变化**。
- 回归 A 序列：`「（注意标签要闭合）」` 随 functionCall 帧发出 → 正文完整 + 调用发射。
- d2 序列：`<DSML|tool_calls>` 以 `<DSML|` 开头 → `withheldStartsWithMarkup=true` → 不补发 → DSML 不泄漏。
- **已知代价**：误扣正文恰好以裸标签开头（如 `<run_command>` 散文行首），且以原生调用收口时仍会丢失。但补丁 3 已将原生流的裸标签 hold 机制关闭（触发面归零）；残余面为「标准标记截断 + 原生收口」的罕见混合帧（H2），可接受。

**回归验证**：h4 双场景（纯文本开头补发 + 标记开头不泄漏）与 h5（`function_call` 旧式收口同样补发）均覆盖此细化逻辑。

### 补丁 3（可选加固，原生路径完全免疫）：裸标签 hold 机制仅在流中无原生 tool_calls 痕迹时启用

```ts

const alreadyInsideToolBlock =
```

**论证**：
- 原生模型正文（含行首裸标签散文）→ 机制关闭 → 不 hold、不截断 → 正文实时发射，**回归 A 触发面归零**；三段原生路径 + 发射层对原生流与 8cf2312^ 完全等价。
- 文本标签模型：流中不会有 `delta.tool_calls` → 机制完整保留 → 泄漏修复（C3/C5 的改进）**不回退**。
- 权衡：先发 native 调用痕迹、后出正文的混合流中，正文裸标签按 8cf2312^ 行为透出（可接受，泄漏影响 < 正文丢失；且 1220-1228 先于发射区记账，天然按 chunk 顺序生效）。
- 注：补丁 3 独立即可消除回归 A，但**不能替代补丁 1/2**（回归 B 与文本模型路径仍需记账修正）。

### 不采纳项及理由

- **「validateForPass 仅最终发射 Pass 严格执行、靠前 Pass 放宽为警告」（hint 方向③）——不采纳**。中间帧（allowUnclosed=false，1304）每帧都跑 Pass1-7，若靠前 Pass 放行未声明名候选，c2 型 bogus call 会在中间帧直接发射并清空上下文（1328-1330）→ 剩余流整段吞 + IDE abort 复发。实测 C4 证明新旧误拒面一致（alias 场景旧版同样拒绝），扩散校验无新增实证回归。
- **「hasUnclosedBareToolBlock 对 BUILTIN 工具名收严判断」（hint 方向②）——不作为独立补丁**。该函数在 8cf2312 已做边界+围栏收严（#2）；剩余误判面 = 行首裸标签散文，属补丁 3 的守卫范围，且声明优先（625-629）使 BUILTIN 兜底仅在代理重启场景生效。禁用 BUILTIN 兜底会破坏恢复场景（前版文档 Patch 6 结论，维持不默认采纳）。
